# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| diff-matches-plan | The Diff's changed files and hunks, read against the plan's Files list, its in-scope and out-of-scope statements, and any Deviations notes (eval: Plan context; live: plan.md) | Pass if every changed file and hunk does something the plan or a recorded deviation asks for, and every change the plan asks for appears in the diff or is disclosed as left out. Fail if the diff touches a file or makes a change the plan does not name and no deviation records, or silently skips a planned change. A folder named in the plan covers files inside it. | required |
| description-matches-diff | Every factual sentence in the PR description and its checklist, read against the Diff | Pass if each claim about what the PR changes, adds, or leaves alone is true of the diff (files, tests, changelog, "no options added", "implements the plan exactly"). Fail if the description claims a change, test, or file the diff does not contain, claims fidelity the diff contradicts, or leaves out a change the diff makes. A claim that something was not added passes if nothing in the diff adds it. | required |
| fix-is-proven | The Test evidence's before and after, read against the Issue's expected result and the plan's Test plan, plus any new or changed test in the Diff | Pass if either: (a) the evidence shows the issue's repro run before and after the fix, and the after names a concrete observable result (printed output, an exit code, a specific error now gone, specific on-screen text or behavior) that matches the expected result and differs from the before; or (b) a new or changed test in the diff asserts the issue's expected result, and a suite run that includes it is reported by its named command. Fail if the after is only a judgment with nothing observable ("works", "fixed", "matches the expected output byte for byte"), if there is no before/after contrast and no asserting test, or if the evidence only exercises a path the change does not touch. | required |
| repo-checks-run | The Test evidence, read against the repo's test suite and the checks the PR template, CONTRIBUTING, or the plan's Test plan name (eval: Repo facts and Plan context; live: .github/PULL_REQUEST_TEMPLATE.md, docs/CONTRIBUTING.md, and scope.md) | Pass if the repo's own test suite (or the suite the plan's Test plan names) is reported as run with its exact command and its outcome: passing, or failing with the reason stated. Counts and pasted output are not required. Other checks the repo lists, such as format or lint, may be reported in a sentence. Live mode on Path Review is stricter: each of the four checks its PR template lists needs its pasted output. Fail if no suite run is named ("tests pass" with no command), or the repo's checks were never run. | required |
| diff-is-clean | Every hunk in the Diff, read against the Issue and the plan's scope | Pass if every hunk serves the fix: no debug prints, no commented-out code, no stray or generated files, no formatting churn, and no refactor or cleanup the issue does not need. Fail if any hunk is debris or an unrelated change, even when the description explains it. | required |
| template-asks-met | The PR description, read against the repo's PR template and CONTRIBUTING asks (eval: Repo facts' pull request and contribution policy lines; live: .github/PULL_REQUEST_TEMPLATE.md and docs/CONTRIBUTING.md) | Pass if every section or item the template asks for is filled in or marked not applicable with a reason, the issue is named, and every ticked box is true of the diff and evidence. Fail if a section the template asks for is missing, a required item (such as a changelog entry or tests) is absent without a reason, or a ticked box is false. | required |
| policy-disclosure-met | The PR description, read against the contribution policy (eval: Repo facts' contribution policy line; live: docs/CONTRIBUTING.md and scope.md house rules) | Pass if the description meets every disclosure the policy states, such as an AI-use disclosure. If the policy states no disclosure requirement, pass and say so. Fail if the policy requires a disclosure and the description leaves it out or contradicts it. | required |
| test-plan-covered | Each item in the plan's Test plan, read against the Test evidence, the Diff's new or changed tests, and the description | Pass if every item the test plan names is covered: its own command and result in the evidence, a new or changed test in the diff that checks it, a specific statement of its result ("no-ampersand control unchanged"), or a plain note that it was left out and why. Fail if a named test case or control is not mentioned anywhere. | preferred |
| title-states-change | The PR title, read against the Diff | Pass if the title says what the change does in a way that matches the diff. Fail if it is vague ("fix bug", "updates") or describes something the diff does not do. | preferred |

## Verdict rule

Accept (submit) only if every required check passes. Reject (hold) if any required check fails. An unclear grade on a required check counts as a fail, because a PR the grader cannot verify from the package is not ready to submit. Preferred checks (test-plan-covered and title-states-change) are reported but never change the verdict.

An honestly disclosed shortfall is not a failure: if the plan's Deviations and the PR description both say plainly what was left out or changed and why, grade diff-matches-plan, description-matches-diff, and test-plan-covered on the disclosed version. Doing less than everything is fine when it is said out loud; doing something different without saying so is drift. This does not cover unrelated changes: those still fail diff-is-clean even when explained.
